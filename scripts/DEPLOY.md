# 배포 자료

> ## ⚠️ 2026-08-19 — 운영 배포는 **GitHub Pages** 입니다
>
> 이 문서는 Cloudflare Pages 를 쓰던 시기에 작성됐습니다. 아래 Cloudflare 관련
> 설명(대시보드 설정·환경변수·`_headers`·`wrangler`)은 **운영에 해당하지 않습니다.**
>
> | | 운영 (`bahnauto.kr`) |
> |---|---|
> | 저장소 | `uriggiri-inc/bahnauto` |
> | 배포 | **GitHub Actions → GitHub Pages** (`.github/workflows/deploy.yml`) |
> | 계기 | `main` 푸시 · 수동 실행 · 15분 예약(노션 변경 시에만) |
> | 도메인 | `public/CNAME` + Pages 설정 |
> | 응답 헤더 | **설정할 수 없습니다.** `_headers` 는 Cloudflare 전용 기능입니다 |
>
> 헤더를 못 쓰기 때문에 검색 차단은 `src/lib/seo.ts` 의 `SEARCH_OPEN` 하나에
> 달려 있습니다 — `robots.txt` 와 페이지 `noindex` 가 전부입니다.
>
> **아래에서 지금도 유효한 부분**: "정식 공개 전 반드시 처리할 것" 점검 목록,
> 개인정보처리방침·약관 관련 미해결 항목, `ANALYTICS_HOSTS` 설명.
> 드래그앤드롭 절은 오프라인 전달 등 예외 상황용으로 남겨둡니다.

```
dist-deploy/
├─ site/        ← 이 폴더를 통째로 드래그앤드롭
└─ DEPLOY.md    ← 이 문서. 업로드하지 마세요
```

> ⚠️ **`DEPLOY.md` 를 `site/` 안에 넣지 마세요.** 이 문서에는 미해결 법무 이슈가
> 적혀 있어서, 업로드 폴더 안에 있으면 `/DEPLOY.md` 로 누구나 읽게 됩니다.

## 드래그앤드롭 방법

**Cloudflare Pages**
1. 대시보드 → Workers & Pages → Create → Pages → **Upload assets**
2. 프로젝트 이름 입력 (예: `bahnauto-preview`)
3. `dist-deploy/site` 폴더를 끌어다 놓기 → Deploy

**Netlify**
1. https://app.netlify.com/drop 접속
2. `dist-deploy/site` 폴더를 끌어다 놓기

둘 다 계정만 있으면 몇 초 안에 URL 이 나옵니다. 별도 설정은 필요 없습니다.

## 이 빌드의 성격

**정적 사이트입니다.** 서버가 없으므로 서버에서 도는 것은 전부 빠져 있습니다.
검토 목적으로는 문제가 없습니다 — 아직 저장소가 연결돼 있지 않아 정식 빌드에서도
폼이 접수되지 않기 때문입니다.

| 항목 | 동작 |
|---|---|
| 26개 페이지 | 정상 |
| 요금 계산기 · Before/After · 체크리스트 · 탭 · 아코디언 | **정상** (전부 브라우저에서 도는 기능) |
| 스크롤 서사 · 각종 애니메이션 | 정상 |
| 상담 신청 / 매니저 지원 폼 | 입력·검증은 되지만 **접수되지 않음**. "검토용 미리보기라 접수가 되지 않습니다" 안내 |
| 이미지 최적화 | 미적용 (원본 그대로 전송) |

내부 검증 화면(`/lab`, `/design-system`)도 포함돼 있습니다. 링크로 연결돼 있지 않고
검색 색인에서도 제외되지만, 주소를 알면 열립니다. 외부 공유가 곤란하면 업로드 전에
`site/lab` 과 `site/design-system` 폴더를 지우세요.

## ⚠️ 정식 공개 전 반드시 처리할 것

1. **약관 적용 범위** — 현재 약관은 반오토를 "가맹점주에게 제공하는 시스템"으로 정의하고
   가맹계약이 없으면 계정을 승낙하지 않습니다(제2조·제7조). 이 사이트는 가맹점이 아닌
   제3자 점주 대상 위탁 관리 서비스를 안내합니다. **위탁 계약의 범위·책임·손해배상
   조항이 약관에 없습니다.**
2. **개인정보처리방침 수집 항목** — 방침 제2조는 상담 수집 항목을 "이름, 연락처"로
   한정하는데 `/contact` 폼은 그보다 많이 받습니다. **방침에 없는 항목 수집은
   그 자체가 개인정보보호법 위반입니다.**
3. **통신판매업신고번호** — 두 법정 문서 어디에도 없습니다. 대상 여부 확인이 필요합니다.
4. **국외이전 고지 — 문구는 넣었고, 이제 법무 검토가 남았습니다.**
   2026-08-27 에 방침에 `제7조의2 (개인정보의 국외 이전)` 을 추가했습니다(사용자 지시).
   아래 초안 문구를 그대로 옮겼고, 제11조에 GA4 거부 방법을 ③으로 덧붙였습니다.
   이전받는 자는 **GitHub, Inc. · Google LLC · Vercel, Inc. 셋(모두 미국)** 입니다.
   **변호사 확인을 받아야 합니다** — 검토받지 않은 문구가 운영 사이트에 올라간 상태이며,
   검토에서 항목·표현이 바뀔 수 있습니다.
5. **개인정보처리방침·약관 원본 .docx 갱신** — 사이트만 고친 항목이 쌓였습니다.
   **원본이 아직 반영하지 못한 것:**

   | 언제 | 무엇을 고쳤나 | 원본 상태 |
   |---|---|---|
   | 2026-08-19 | 제7조 위탁 표 `Cloudflare, Inc.` → `GitHub, Inc.` (홈페이지 호스팅) | 아직 `Cloudflare` |
   | 2026-08-19 | 제7조에 `Google LLC` 행 추가 (GA4) | 없음 |
   | 2026-08-27 | 제7조에 `Vercel, Inc. — 반오토 시스템 호스팅` 행 추가 | 없음 |
   | 2026-08-27 | 방침·약관 적용 범위에 `bahnauto.kr` 추가 | `uriggiri.kr` 하나뿐 |
   | 2026-08-27 | 제7조의2 국외이전 조항 · 제11조 ③ GA4 거부 방법 추가 | 없음 |

   두 문서가 어긋난 상태이므로 원본을 같은 값으로 맞춰야 합니다. **어느 쪽이 진본인지
   알 수 없게 되는 것이 개별 문구의 오류보다 위험합니다.**
6. **표시광고법** — 위 "샘플 데이터"를 실제 값으로 바꾸고 `content/dummy.ts` 의
   `DUMMY_CONTENT` 를 `false` 로 내려야 배너가 사라집니다.
7. **검색 차단 해제** — `src/lib/seo.ts` 의 `SEARCH_OPEN` 을 `true` 로 바꿔야
   검색에 노출됩니다. 지금은 `false` 이고, 더미 데이터가 색인되면 안 되므로
   그대로 둡니다. **이 한 줄이 오픈의 마지막 단계입니다.**

   ⚠️ 예전 판에는 여기에 "`public/_headers` 의 `X-Robots-Tag` 를 지우라" 고
   적혀 있었습니다. **그 파일은 이 저장소에 없습니다** — `_headers` 는
   Cloudflare 전용 기능이고 GitHub Pages 는 응답 헤더를 설정할 수 없습니다.
   즉 이중 방어가 없고 `SEARCH_OPEN` 이 **유일한** 차단 장치입니다.

## GA4 (Google Analytics 4)

측정 ID `G-5TRWDY543B`. 코드는 `src/lib/analytics.ts` 와
`src/components/analytics/GoogleAnalytics.tsx` 두 파일뿐입니다.

**수집 대상은 호스트 이름이 정확히 일치할 때로 한정됩니다.** 허용 목록은
`ANALYTICS_HOSTS` 한 줄이고 현재 값은 `banauto.pages.dev` 하나입니다.

| 환경 | 호스트 | 수집 |
|---|---|---|
| 운영 | `banauto.pages.dev` | O |
| 로컬 개발 | `localhost` | X |
| Pages 브랜치 프리뷰 | `<해시>.banauto.pages.dev` | X (부분일치를 허용하지 않음) |
| Workers 프리뷰 | `*.workers.dev` | X |

허용되지 않은 호스트에서는 `googletagmanager.com` 요청 자체가 나가지 않습니다.
`config` 만 건너뛰면 스크립트 로드만으로 세션이 잡히기 때문입니다.

GA4 는 `(site)` 레이아웃에만 붙어 있습니다. 루트에 두면 `/design-system` 과
`/lab` 의 내부 확인 트래픽이 섞입니다 — 두 화면은 운영 도메인에도 올라가 있어
호스트 검사로는 걸러지지 않습니다.

**커스텀 도메인이 확정되면** `ANALYTICS_HOSTS` 에 추가하세요. `www` 를 쓸
계획이면 `www.` 붙은 것도 함께 넣어야 합니다 — 빠뜨리면 www 유입이 통째로
집계에서 사라집니다.

> 참고: 개인정보처리방침 도입부는 회사 홈페이지를 `uriggiri.kr` 로 적고 있습니다.
> 반오토 홈페이지의 최종 도메인이 확정되면 방침 도입부와 `ANALYTICS_HOSTS`,
> `metadataBase` 를 함께 맞춰야 합니다.

## Git 연동 (Cloudflare Pages)

저장소: `https://github.com/twintwin3h-hun/banauto` (`main` 브랜치)

대시보드 → Workers & Pages → Create → Pages → Connect to Git

| 설정 | 값 |
|---|---|
| Framework preset | `None` |
| Build command | `npm run build` |
| Build output directory | `out` |
| Root directory | 비움 (저장소 최상단이 프로젝트 최상단) |

**환경변수는 필요 없습니다.** Cloudflare Pages 가 자동으로 넣는 `CF_PAGES=1` 을
`next.config.ts` 가 읽어 정적 내보내기로 전환합니다. 사람이 대시보드에
`STATIC_EXPORT` 를 손으로 넣어야 했던 시절에는, 그걸 잊으면 `out/` 이 생기지 않아
**모든 경로가 404** 가 됐습니다. 기억에 의존하는 설정은 언젠가 어긋납니다.

Node 버전은 저장소의 `.node-version`(=22) 으로 고정됩니다.

### 404 가 날 때 확인 순서

1. **Build output directory 가 `out` 인가** — 비어 있으면 저장소 최상단을 배포한다.
   거기에는 `index.html` 이 없으므로 전 경로가 404 다. 가장 흔한 원인.
2. **빌드가 끝까지 성공했는가** — 배포 로그 마지막에 `Success: Assets published!`
   와 업로드 파일 수(약 190개)가 찍혀야 한다. 중간에 멈췄으면 올라간 게 없다.
3. **Build command 가 `npm run build` 인가**

### 예상 산출물

`out/` — 파일 190개 / 약 5.9MB / HTML 27개. Pages 한도(파일 2만개, 개당 25MB)에
한참 못 미칩니다.

> `wrangler.jsonc` 는 Workers 용 설정입니다. Pages 빌드는 `pages_build_output_dir`
> 키가 없는 이 파일을 **무시하고 경고만 남깁니다**(로컬 개발용으로만 사용).
> 배포를 막지 않으니 그대로 두면 됩니다.

## 정식 배포(서버 포함)

폼 접수까지 동작하는 배포는 Cloudflare Workers 로 합니다.

```bash
npm run build:cf
npx wrangler login   # 최초 1회
npx wrangler deploy
```

> ⚠️ `wrangler deploy` 는 외부 공개입니다. CLAUDE.md §1.3 에 따라 실행 전 확인을 받으세요.
